Segment 01 // The Distinction

A chatbot answers. An agent finishes the job.

Most people in this room have used AI as a very fast writer. That is a chat window. An agent is the same underlying model, but you hand it a standing set of instructions, point it at the material it is allowed to read, and give it a few things it is allowed to do. Then it works without you retyping the setup every single time.

// What most people are doing today
Chat Window

You are the memory, the file cabinet, and the quality control.

  • You re-explain your role and the format every time you open it
  • You paste in the document, then paste in the next document
  • It forgets your standards the moment you close the tab
  • Two people asking the same question get two different answers
  • Good output, but it lives and dies in one conversation
// What we are building today
Agent

You set it up once. Everyone else just asks.

  • The instructions are baked in, so the role never has to be re-explained
  • It already knows where the source documents live
  • It can take actions: search, retrieve, draft, populate, hand off
  • Everyone on the team gets the same answer to the same question
  • You can share it, version it, and improve it over time

A chat window is a conversation. An agent is a coworker you configured, and configuring one is closer to writing a job description than it is to writing code.

Segment 02 // Transferable Skill

Five parts. Every agent. Every model.

This is the part worth writing down. Every agent platform on the market is built from the same five parts. The vendors name them differently, and the buttons sit in different places, but the job is identical. Pick a platform below and watch the labels change while the parts stay exactly where they are.

PART 01
📋
Instructions

Who it is, what it does, what it never does, and what the output should look like. This is the job description.

PART 02
📚
Knowledge

The documents and data it is allowed to read. Without this it answers from general training, which is how you get confident nonsense.

PART 03
🔧
Tools

The actions it can take outside the chat box: search a system, pull a record, populate a file, send a draft somewhere.

PART 04
🧠
Memory

What it carries between turns and between sessions. This is why the second question does not need the first one repeated.

PART 05
🛡️
Guardrails

Who can use it, what data it may touch, and where a human has to sign off. In our environment this part is not optional.

Segment 04 // Applied

What this looks like here

The best first agent is a task you already do every week, that follows a pattern, and that does not require judgment you would be uncomfortable delegating. Four starting points, all unclassified, all built from the same five parts.

Segment 05 // Non Negotiable

The rules that come with the keys

An agent is faster than a person and just as wrong when it is wrong. These six hold whether you are building in Gemini Enterprise or anywhere else.

// Rail 01
Data stays in its lane

Only put data into a system that is accredited to hold it. The agent inherits the boundary of the platform it sits on, not the boundary you wish it had.

// Rail 02
A human signs

The agent drafts, retrieves, and organizes. A person still owns the product and the decision. Speed is the benefit, accountability does not move.

// Rail 03
Ground it or expect drift

An ungrounded agent will fill gaps with something plausible. Point it at approved sources and require citations so the answer is checkable.

// Rail 04
Least privilege applies

Give the agent the smallest set of documents and actions the job requires. Access you grant is access it will use, including on a bad day.

// Rail 05
Test it against known answers

Before anyone else touches it, ask it ten questions you already know the answer to. An agent you have not tried to break is not ready to share.

// Rail 06
Follow the standing guidance

DoD responsible AI is not a slogan: responsible, equitable, traceable, reliable, governable. Check current command policy before you field anything.

Reference // Plain English

Words you will hear today

No jargon defenses. If someone uses one of these in a meeting, this is what they mean.

// TERM-01
Agent

An AI setup you configure once so it can do a job repeatedly. It has standing instructions, a set of documents it can read, and a few actions it is allowed to take.

// TERM-02
Large Language Model

The engine underneath. It predicts language extremely well, which is why it can write, summarize, and answer. Gemini, Claude, and GPT are all engines of this kind.

// TERM-03
Grounding

Forcing the AI to answer from documents you provided rather than from memory. Grounded answers can be checked against a source. Ungrounded answers cannot.

// TERM-04
Hallucination

When the model states something false with total confidence. It is not lying, it is completing a pattern. Grounding and verification are the fix.

// TERM-05
Tool Calling

Letting the AI reach outside the chat box to do something: run a search, pull a record, fill a file. This is what turns an assistant into an agent.

// TERM-06
Context Window

How much the model can hold in front of it at one time. Large but not unlimited. Push past it and the earliest material falls off the back.

// TERM-07
System Prompt

The standing instructions that load before anyone types a word. Same idea as a job description, and it is where most of the quality comes from.

// TERM-08
Connector

A pipe between the agent and a system that holds your information. Connectors are how an agent reads real data instead of what you paste in.
